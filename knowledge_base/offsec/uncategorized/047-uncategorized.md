## Scenario

Why does spending months on one program beat jumping between many targets?

## Analysis / Response

Because depth compounds. You can't find all the bugs in weeks - large companies have lots to play with and ship new features constantly. By committing months you:

- Build a complete mental mind-map of the application plus written notes: interesting functionality, subdomains, vulnerable parameters, bypasses used, bugs found. That becomes a starting point to jump back in anytime.
- Learn how the developers think from how they patch and when features appear (new bugs, or old bugs reintroduced?). Patches reveal their mental model, which you then apply elsewhere.
- Catch new attack surface as it lands - new features mean new bugs, and bigger companies release changes more frequently.
- Benefit from re-testing: you can never see everything on the first look (I've gone through some assets 50+ times), and features often need re-testing because results only appear after a multi-step flow completes.

It doesn't happen in days, so be patient and trust the process. Once you internalise the flow, you can rotate across 5-6 wide-scope programs and always have something to play with - but each one is a long-term relationship, not a smash-and-grab. Authorized scope only.
