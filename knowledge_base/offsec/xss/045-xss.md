## Scenario

I'm stuck on the PortSwigger lab "DOM XSS in document.write sink using source location.search" (Apprentice, Cross-site scripting). Here's the scenario:

This lab contains a DOM-based cross-site scripting vulnerability in the search query tracking functionality. It uses the JavaScript `document.write` function, which writes data out to the page. The `document.write` function is called with data from `location.search`, which you can control using the website URL.

To solve this lab, perform a cross-site scripting attack that calls the `alert` function.

Please give me the step-by-step solution.

## Analysis / Response

This PortSwigger Web Security Academy lab (Apprentice) covers Cross-site scripting: "DOM XSS in document.write sink using source location.search".

## Solution steps

1. Enter a random alphanumeric string into the search box.
2. Right-click and inspect the element, and observe that your random string has been placed inside an `img src` attribute.
3. Break out of the `img` attribute by searching for: `"><svg onload=alert(1)>`

## Vulnerability note

Underlying issue: Cross-site scripting (CWE-79). Prevent XSS with context-aware output encoding, Content-Security-Policy, and avoiding unsafe sinks like innerHTML with untrusted data.
